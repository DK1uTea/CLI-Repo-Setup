# Maintain create-my-stack

This repository is a generator. Distinguish the root CLI from the two application templates and from a project generated by the CLI. Start with `README.md`; read `docs/architecture.md` for scaffold flow and `docs/template-maintenance.md` for template edits or refreshes.

## Route the task

- CLI flags and defaults: inspect `src/cli.ts`, `src/prompts.ts`, `src/types.ts`, and `src/validate.ts` together.
- Copying, exclusions, destination conflicts, backend app renaming, and generated config: inspect `src/scaffold.ts`.
- Text replacement and project-name variants: inspect `src/placeholders.ts`; preserve the four-placeholder contract and Docker/YAML special case unless the request changes it.
- Git, installation, upgrades, and printed commands: inspect `src/post.ts` and `src/pm.ts`.
- Checked-in template source: inspect the relevant `templates/fe` or `templates/be` files and that template's local instructions. For FE, read `templates/fe/AGENTS.md` before edits under that subtree.
- Template regeneration: inspect `scripts/prepare-templates.mjs` and the configured upstream paths first. It removes and recreates both template directories.

## Invariants to preserve

- Source template `noCheck` and BE `types: []` exist to keep incomplete source templates quiet in the root editor. Generated projects must omit `noCheck` and restore BE `types: ["multer"]`. Keep the source configs, scaffold transform, and preparation script consistent.
- The generated backend app folder must be renamed from `apps/__projectName__`; replacing text placeholders alone does not rename it.
- `_gitignore` and `_npmrc` are source-template packaging names and become dotfiles in generated projects.
- A root `pnpm typecheck` checks only CLI source. For template behavior, inspect a generated project; when application compilation matters, install its dependencies and run its own build.
- `--yes` has operational defaults: Git, install, and latest upgrade are enabled unless explicitly disabled. Use explicit `--no-install --no-git --no-latest` for disposable offline scaffold checks.
- Existing destination modes differ: overwrite clears existing content; merge keeps unrelated files and is not rolled back on failure.
- Keep root unit tests under `tests/` with paths mirroring `src/` or importable helpers under `scripts/` (for example, `src/post.ts` maps to `tests/src/post.test.ts`). Template-local tests belong to generated applications and stay under their respective `templates/` trees.

## Verification

Choose the smallest checks that cover the changed path. For CLI changes, run `pnpm typecheck`, `pnpm lint`, `pnpm build`, and `pnpm test` as relevant. For template/config changes, scaffold FE and BE into disposable directories and inspect the generated output. Use the optional full install/build suite when dependency or generated-app compilation is at issue. Keep `README.md` and the focused docs accurate when behavior changes.

The root commit gate is `pnpm verify:commit`, invoked by `.husky/pre-commit`. It runs lint, typecheck, build, and normal tests; the full generated-project install/build suite is separate. Keep this gate synchronized with package scripts and documentation.

For new CLI behavior or a bug fix, use a red → green → refactor loop: write the expected behavior as a test in the mirrored `tests/src/` or `tests/scripts/` path (or a CLI E2E test if process-level behavior is essential), verify the test fails for the intended reason, implement the minimal fix, then run it and the relevant checks again. For coverage of existing behavior, write characterization tests without changing source just to force a failure. The FE template's separate QA/dev test ownership rules apply inside that template, not automatically to the root CLI.
